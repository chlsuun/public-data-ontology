# 질문 중심 공공데이터 Discovery Platform v0.3

[프로젝트 요구사항](requirements-v0.3.md)을 반영해 **질문 → 개념 → 지표 → 데이터셋 → 제공기관**을 중심으로 온톨로지를 구성했다. 국내외 전 분야를 수용하며, 메타데이터·관계·출처를 지속적으로 축적하는 구조다. 처음 보는 팀원은 [저장소 안내](../../README.md)와 [공유 가이드](../../docs/team-guide.md)부터 읽으면 된다.

이전의 [국내 제공처 122개 조사](../national-catalog/README.md)는 수집 출처를 관리하는 기반으로 유지했다. 이번에는 OECD·World Bank 2개 제공처를 추가해 124개 조사 항목을 연결하고, 첨부 문서의 청년 인구 유출 질문으로 탐색 구조를 구체화했다. **예시 자료 6개는 전체 서비스 범위를 제한하지 않는다.** 국내외 전수 목록 수집 완료를 뜻하지도 않는다.

## 실제로 바뀐 것

| 항목 | 반영 결과 |
|---|---|
| 그래프의 중심 | 포털 목록에서 사용자 질문·개념·지표로 이동 |
| 지표 개체 | 전입·전출·순이동·실업률·고용률·주택가격·임대료·졸업 후 이동·NEET을 구분 |
| 관계 DB | 관계마다 출처·상태·탐색 역할·설명 경로를 저장 |
| 국제 범위 | OECD·World Bank의 실제 지표 설명·자료 안내와 World Bank 메타데이터 API 2건 확인 |
| Harness | 깊이·노드·관계·자료 후보·검사한 관계 수·탐색 시간 상한을 로컬 탐색기에 적용 |
| 자원 설계 | 모델 호출·재시도·동시 요청·메모리·임시 디스크·캐시·감사 기록 한도를 별도 정책으로 명세 |
| 시각화 | 질문 중심 관계와 시스템 자원 제어 구조를 탐색할 수 있도록 재구성 |

## 파일을 읽는 순서

1. [재구성 설계서](architecture.md): 제품 범위·질의 흐름·관계 의미·AWS 방향과 문서에서 보완한 부분.
2. [관계 모델](model.json): 질문·개념·지표·자료·제공기관 및 근거가 있는 관계.
3. [Harness 정책](harness-policy.json): 요청별 한도와 실제 구현 여부.
4. [예시 탐색 결과](example-results.json): 각 자료를 추천한 연속 경로와 미확인 조건.
5. [검증 결과](validation-report.json): 참조·출처·예산 제한·후보 상태에 관한 19개 검사.

`source-observations.json`은 직접 수집한 메타데이터·공식 문서의 관찰 기록이고, `source-reviews.json`은 웹 도구로 확인한 OECD 설명·연결 주소와 수동 검토 근거다. OECD의 로컬 요청 실패 기록은 웹 도구의 성공 기록과 구분해 보존했다. 첨부 문서의 사본은 [요구사항](requirements-v0.3.md)에 있으며, 그 문서의 가설을 통계적 사실이나 실제 서비스 운영 증거로 사용하지 않는다.

## 지금 볼 수 있는 결과

기본 청년 인구 유출 예시는 **23개 노드, 27개 관계, 6개 자료 후보**를 반환한다. 깊이를 1로 줄이면 직접 인구이동 자료 2개까지 탐색하고, 깊이 2에서는 고용·주거·교육의 맥락까지 넓힌다.

실제 자료 설명을 확인한 것과 요청에 적합한 하위계열·결합 조건까지 검증한 것은 다르다. KOSIS는 공식 목록의 통계표 ID를 확인했으나 원본 표 직접 접근을 완료하지 못했다. OECD의 일부 기본 조회 조건은 청년 지표와 다르다. 따라서 자료 추천에는 후보 상태와 필요한 확인을 함께 반환한다. 졸업 후 지역 이동과 NEET의 적절한 자료 대응은 미해결로 남겼다.

## 구현 수준

- 구현: JSON 관계 DB 프로토타입, RDF 교환 파일, 예산을 적용한 로컬 그래프 탐색기, 추천 경로·근거 반환, 인터랙티브 설명.
- 설계: FastAPI, 외부 LLM 요청·승격, PostgreSQL 운영 저장소, 컨테이너·동시성·임시 작업공간 한도, 영속 감사 기록.
- 미실행: 실제 OpenAI 호출, AWS 배포, 원본 관측값 수집·결합, 통계적 상관분석, 법률·개인정보 판단 자동 집행.

LLM·서버 기능을 연결한 것처럼 보이게 하기 위해 가짜 API 결과나 추정 상관계수를 넣지 않았다. 현재 질문 3개는 편집한 탐색 예시이며 자유로운 자연어 이해 모델이 실행되는 화면은 아니다.

## 재현

프로젝트 루트에서 다음 명령으로 저장된 근거를 사용해 다시 생성하고 검증할 수 있다. 네트워크·LLM 호출은 없다.

```powershell
python ontology-prototype/discovery-platform/build_model.py
python ontology-prototype/discovery-platform/explore.py
python ontology-prototype/discovery-platform/validate.py
```

Python과 rdflib가 필요하다. `python -m pip install -r ontology-prototype/requirements.txt`로 설치하며 가상환경 사용 방법은 저장소 루트 README를 따른다. `collect_sources.py`는 실제 외부 요청을 수행하는 별도 조사 도구이며 기존 관찰 파일을 덮어쓰지 않는다. 정규화 모델은 `build_model.py`, 정책은 `harness-policy.json`을 수정한 뒤 생성한다. 공유용 그래프는 프로젝트 루트에서 `python scripts/build_shared_graph.py`로 재생성한다.

초기 개발 우선순위는 전체 제공처 목록 보완, 자료 메타데이터 수집기, 개념·지표 대응 검토, PostgreSQL에서의 탐색 상한 구현, 제한된 LLM 질의 해석 연결 순이다. 연구 예시 하나의 지표를 서비스 전체의 고정 분류로 쓰지 않는다.
