# 국내 공공데이터 제공처 조사와 공통 온톨로지 v0.2

현재 제품 설계는 첨부 요구사항을 반영한 [질문 중심 Discovery Platform v0.3](../discovery-platform/README.md)으로 확장했다. 이 폴더의 국내 조사 기록은 원래 범위와 확인 상태를 유지한다.

조사 기준일: 2026-09-12. 국내 전 분야·전 지역의 공식 데이터 제공처를 대상으로 하는 첫 조사 결과다.

공공데이터포털 하나에 한정하지 않고, 통계·분야별 포털, 지자체 포털, 기관의 데이터 개방 메뉴·API 안내까지 같은 구조에 등록했다. **이번 결과는 제공처 조사 등록부와 관계 설계의 출발점이다. 전국 모든 제공처나 모든 데이터셋을 수집한 결과는 아니다.**

등록부의 조사 분류는 통합 4개, 통계 5개, 분야 58개, 지역 38개, 기관 17개다. 이 분류와 주제는 프로젝트가 조사 편의를 위해 붙인 값이며 포털 원문 분류체계를 수집한 결과는 아니다.

122개 항목 중 본문을 관찰한 항목은 75개, 제목만 확인한 항목은 24개, 응답만 확인한 항목은 13개, 중간·점검 화면은 3개, 조회 미해결은 7개다. 본문 확인은 자동 수집으로 일정 길이의 텍스트를 얻었다는 뜻이다. 전체 기능이 정상 운영된다는 검증은 아니다. 조회 실패도 서비스 종료로 해석하지 않는다.

기관 목록은 다음 공식 출처를 사용했다. 원문과 조회일은 관찰 파일에 보존했다.

## 온톨로지에 반영한 것

구조는 **제공처 → 데이터 목록 → 포털별 등록정보 → 실제 자료 → 배포 파일·API 및 컬럼 구조 → 공통 개념**으로 이어진다. 각 관계에는 근거와 확인 상태를 붙인다.

- **규칙 정의**: 26개 개체 유형과 16개 프로젝트 관계를 정의했다. 목록·자료·배포 표현은 [DCAT 3](https://www.w3.org/TR/vocab-dcat-3/), 개념 관계는 [SKOS](https://www.w3.org/TR/skos-primer/), 출처·실행 표현은 [PROV-O](https://www.w3.org/TR/prov-o/)를 참고한 로컬 설계다.
- **실제 기록**: 제공처 조사 항목, 편집자가 붙인 주제, 관찰한 하이퍼링크, 출처 기록, 기관 관계 주장들을 JSON과 RDF로 작성했다.
- **상태 구분**: 후보인 운영기관 관계는 실제 운영 사실로 출력하지 않는다. 단순 링크를 자료 동일성·API 연동·데이터 동기화로 바꾸지 않는다.
- **후속 양식**: 데이터 등록정보, 컬럼·차원·측정항목, 근거가 있는 관계를 기록할 빈 양식을 만들었다.

RDF의 `https://example.org/kr-public-catalog/`는 프로토타입용 임시 식별자다. 공식 인증 온톨로지나 실제 서비스 주소가 아니다. 현재 홈페이지 조사 항목은 `ServiceEntry`로 표현했으며, 자료 목록을 확인하기 전에는 모두 `Catalog`로 선언하지 않았다.

## 네가 맡은 관계 정의 작업에 쓰는 방법

1. **제공처 조사표에서 한 항목을 연다.** 안내 경로를 따라 실제 데이터 목록, 상세 설명, API 문서를 확인하고 원문 주소와 확인일을 남긴다.
2. **등록정보를 출처별로 기록한다.** 제목·제공기관·분야·기간·지역·이용 조건을 원문 그대로 보존한다. 포털마다 같은 제목이 있어도 먼저 별도 등록정보로 둔다.
3. **구조 설명을 기록한다.** 실제 헤더나 설명서에서 항목명·의미·단위·코드 체계·시간·공간 기준을 확보한다. 통계표는 컬럼 대신 차원과 측정항목을 조사할 수 있다.
4. **관계를 근거와 함께 제안한다.** ‘같은 주제’, ‘같은 자료일 가능성’, ‘지역·기간을 맞추면 결합할 후보’ 등을 구분하고 미확인 조건을 적는다.
5. **수치 상관분석은 질문과 변수 쌍이 정해졌을 때 한다.** 실제 값과 분석 조건을 확보한 뒤 결과를 별도 분석 기록으로 남긴다. 모든 포털의 모든 컬럼 쌍에 상관계수를 계산하는 작업으로 시작하지 않는다.

이 과정에서 사용하는 양식은 [등록정보 양식](registration-template.json), [변수 양식](variable-template.json), [관계 양식](relationship-template.json)이다. 모두 `template_only: true`인 빈 양식이며 실측 결과를 담고 있지 않다.

## 개발용 파일과 재현

| 종류 | 파일 |
|---|---|
| 편집 원본 | `service-seeds.json`, `discovered-services.json`, `service-reviews.json`, `ontology-profile.json` |
| 정규화 등록부 | `portal-registry.json`, `institution-review-status.json`, `navigation-review-queue.json` |
| 근거 색인 | `source-evidence.json` — 원문 관찰 파일과 기록 ID를 연결 |
| 원문 관찰 | `directory-observations.json`, `directory-detail-observations.json`, `page-observations.json`, `discovered-page-observations.json`, `institution-site-observations.jsonl` |
| 기관 모집단 | `institution-review-queue.json`, `alio-roster.json` |
| RDF 산출물 | `common-ontology.ttl`, `portal-registry.ttl` |
| 수집 프로그램 | `research_fetch.py`, `enumerate_institutions.py`, `scan_institution_sites.py` |
| 생성·검증 | `build_catalog.py`, `validate_catalog.py` |

현재 워크스페이스에서 다음 명령은 저장된 관찰 파일로 문서·JSON·RDF를 다시 생성하고 검증한다. 네트워크나 LLM 호출은 없다.

```powershell
python ontology-prototype/national-catalog/build_catalog.py
python ontology-prototype/national-catalog/validate_catalog.py
```

생성·검증에는 Python과 rdflib가 필요하다. 프로젝트 루트에서 `python -m pip install -r ontology-prototype/requirements.txt`로 설치한다. 수집 프로그램은 표준 라이브러리를 사용하며 실제 외부 요청을 수행하므로 오프라인 재생성과 구분한다. 새 조사 시에는 이전 관찰 파일을 보존한 별도 버전을 만들어 출처 변경 이력을 유지한다.

## 다음 실행 범위

포털·분야 범위를 넓게 유지하면서, 추가 경로 후보 검토와 기관 모집단 보완을 진행한다. 확인한 제공처별로 전체 목록을 얻는 방법·페이지 처리·인증·호출 조건을 명세화한 다음, 등록정보와 구조 설명을 수집한다.

이번 단계의 전체 데이터 목록 수집, 개별 자료 API 실행, 실제 자료 결합은 각각 0건이다. 이용 조건·품질·개인정보 검증 결과, LLM 추천, 정책 집행, 거래 기능은 아직 구현하지 않았다. 현재 14개 검사는 출처·참조·상태·수집 집계·RDF의 일관성을 확인한다.
