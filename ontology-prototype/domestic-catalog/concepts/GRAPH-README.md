# 공공데이터 전체 출처 지식 그래프

[전체 지식 그래프 열기](http://127.0.0.1:8766/concepts/graph)

어느 포털의 어떤 자료와 원문 항목이 공통 개념의 근거인지 따라가는 그래프다. 공통 개념은 프로젝트에서 정리한 88개 정의 초안이며, 포털이 같은 온톨로지를 공식 제공한다는 뜻은 아니다.

## 화면에서 사용하는 방법

1. **큰 화면**을 누르면 넓은 화면에서 전체 그래프를 볼 수 있다. **작게 보기**나 Esc로 돌아온다.
2. 왼쪽 포털 노드, 오른쪽 개념 노드 또는 위의 선택 목록을 선택한다. 해당 조건의 모든 포털–개념 연결을 강조한다.
3. **출처 경로 펼치기**를 누르면 `포털 → 데이터셋 등록정보 → 원문 칼럼·분류 → 공통 개념 후보`로 펼쳐진다.
4. 원문 항목 노드를 누르거나 **원문 근거 확인**을 누르면 설명·자료형·단위·출처 URL·조회일·원문 해시·저장 위치를 확인한다. 데이터셋 노드에는 제공기관과 전체 칼럼을 확인하는 링크가 있다.
5. 한 화면에는 원문 항목 24개씩 표시한다. **이전/다음**으로 조회 결과 전체를 탐색할 수 있다. 전체 화면에도 페이지 버튼이 있다.
6. **개념 미연결 항목도 조회**를 선택하면 현재 88개 개념에 매핑되지 않은 항목도 검색한다. **원문 항목명** 검색과 **근거 종류** 필터를 함께 사용할 수 있다.
7. **미수집 후보 포함**은 아직 목록을 확보하지 못한 포털 후보도 보여준다. 근거가 없는 후보에는 데이터나 개념 연결을 생성하지 않았다. **선택 해제**는 전체 수집 연결로 돌아간다.
8. **등록 자료**는 원문 항목 유무와 관계없이 수집한 모든 등록정보를 포털별로 보여준다. 자료를 선택하면 제공기관과 원문 링크를 볼 수 있고, 해당 자료에 저장된 원문 항목으로 이어갈 수 있다.

휠 또는 ＋/－로 확대·축소하고, 빈 공간을 드래그해 이동한다. 노드를 드래그해 위치를 조정할 수 있다. 키보드 방향키, ＋/－, 0(맞춤)도 지원한다. 모든 포털·개념은 일반 선택 목록으로도 접근할 수 있다.

## 이번 스냅샷의 범위

정확한 생성 시각과 수량은 [그래프 개요 JSON](graph-overview.json)과 [빌드 기록](graph-build-report.json)에 저장한다.

| 구분 | 수량 | 해석 |
|---|---:|---|
| 조사 등록부의 국내 포털·입구 후보 | 125곳 | 국내 전수 명부가 아니다 |
| 등록정보를 확보한 포털 | 32곳 | 각 포털의 전체 수집 완료를 뜻하지 않는다 |
| 공통 개념과 연결 후보가 있는 포털 | 21곳 | 나머지 11곳은 등록·원문을 보존하고 개념 연결을 임의 생성하지 않음 |
| 데이터셋 등록정보 | 440,356건 | 포털별 등록 건이며 동일 자료를 자동 병합하지 않는다 |
| 공통 개념 초안 | 88개 | 16개 분야, 8가지 역할 |
| 포털–개념 연결 후보 | 433쌍 | 실제 원문 항목 연결을 포털별로 집계 |
| 개념 연결 출현 | 260,507건 | 표기 일치·명시적 출처 범위에 따른 후보. 반복 출현 포함 |
| 검색 가능한 원문 항목 | 4,122,591개 | 원분류·키워드 2,008,637개 + 명세 1,473,095개 + 목록 출력 후보 640,859개 |
| 공통 개념에 연결된 원문 항목 | 257,597개 | 한 항목이 여러 개념 후보에 연결될 수 있어 위의 연결 건수와 다르다 |
| 공통 개념 미연결 원문 항목 | 3,864,994개 | 삭제하지 않고 원문 검색에 보존 |
| 출처·역할·표기별 용어 묶음 | 720,861개 | 고유 의미 개념 수가 아니다 |

예를 들어 KOSIS에는 52개 공통 개념에 대한 원문 근거 후보가 있다. KOSIS의 실업률 명세 항목은 40개이며, 기존 개념 화면의 소수 예시를 반복해서 확장한 것이 아니라 저장된 명세 전체에서 찾은 결과다.

원본 표준 명세의 기관별 연결, 여러 통계표에 반복된 분류·항목명, 등록 버전에 따른 반복을 포함한다. API 제어 항목 중 분리 규칙에 해당한 68,403개는 공통 개념 매핑에서 제외하고 원문 항목으로 보존한다. 파일 미리보기 머리글 후보, 요청 인자, 기관의 비공개 DB, 실제 관측값은 이 그래프 항목 집계 범위에 포함하지 않는다.

그래프는 고정 스냅샷이다. 백그라운드 수집이 계속되는 검색 DB보다 시점이 이전일 수 있다. 이전 개념 사전의 511,089개 용어 묶음은 별도 생성 시점과 추출 범위를 사용한다. 새 그래프는 목록 출력 후보와 제어 항목 표기도 포함하므로 두 수량을 같은 지표로 비교하지 않는다.

## 선의 의미

| 연결 | 상태 | 뜻 |
|---|---|---|
| 포털 → 데이터셋 등록정보 | 원문에 기록된 소속 | 해당 포털 목록에서 확인한 등록 건 |
| 등록정보 → 원문 항목 | 원문 또는 저장 파서 결과 | 칼럼 명세, 원분류·키워드, 출력 문자열 후보를 각각 구분 |
| 원문 항목 → 공통 개념 | 사람 검토 전 후보 | 이름·표기 및 출처 범위에 따른 의미 연결 가설 |
| 전체 화면의 포털 → 공통 개념 | 후보 경로 집계 | 위의 실제 출처 경로들을 합친 개요 연결 |
| 공통 개념 → 분야 | 탐색용 배치 제안 | 하위 클래스나 통계적 상관관계가 아니다 |

개념 정의·동의어·단위 환산·자료 간 코드 동등성·결합 가능성·상관관계는 자동 승인하지 않는다. 데이터 품질 점수도 이번 그래프의 연결 수나 원문 출현 수로 계산하지 않는다. 제공기관 식별자는 출처 포털의 이름공간을 보존하며, 다른 포털의 같은 이름 기관과 자동 통합하지 않는다.

## 파일과 재생성

- `graph.html`: 전체 지도와 출처 경로 탐색 화면.
- `graph-overview.json`: 모든 포털·88개 공통 개념·포털별 연결 집계·범위·생성 시각. 수백만 개 원문 항목을 이 JSON 하나에 넣지는 않는다.
- 프로젝트 루트의 `.local/domestic-catalog/knowledge-graph.sqlite3`: 전체 등록정보, 모든 원문 항목, 용어 묶음, 항목–개념 연결, 집계의 조회 인덱스.
- `graph_api.py`: 개요, 출처 경로 페이지, 항목 상세에 대한 읽기 전용 API.
- [전체 그래프 검사](graph-validation.json), [화면 검사](graph-ui-check.json).
- 이전 `concept-model.json` 및 `review-queue.json`은 개념 정의와 검토 예시를 유지한다. 새 전체 그래프의 후보가 사람의 승인으로 자동 반영되지는 않는다.

프로젝트 루트에서 실행한다.

```powershell
python -X utf8 ontology-prototype/domestic-catalog/concepts/build_graph.py
python -X utf8 ontology-prototype/domestic-catalog/concepts/check_graph.py
```

검사에는 로컬 검색 서버가 필요하다. 빌더는 원본 검색 DB를 읽기 전용으로 열고 별도 그래프 인덱스를 만든 뒤 교체한다. 중단된 빌드 임시 파일이 있으면 자동으로 덮어쓰지 않고 확인을 요구한다. 항목의 숫자 ID와 페이지 순서는 해당 그래프 스냅샷에 한정되며, 장기 검토 근거에는 원본 등록 ID·근거 ID·칼럼 순번·원문 위치를 함께 사용한다.

전체 원문 항목은 `items`, 자료는 `records`, 항목–개념 연결은 `mappings` 테이블에 있다. `items.record_id → records.id`, `mappings.item_id → items.id`, `mappings.concept_id → graph-overview.json의 concepts.id`를 연결하면 화면에 표시되는 모든 출처 경로를 재구성할 수 있다.
